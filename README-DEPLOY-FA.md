# راهنمای استقرار «عمارت رنگین» — GitHub + Turso + Vercel

این سند قدم‌به‌قدم تمام کاری را که باید انجام دهی توضیح می‌دهد تا بازی روی اینترنت عمومی شود:

| سرویس | نقش | هزینه |
|---|---|---|
| **GitHub** | نگهداری کد (نسخهٔ اصلی پروژه) | رایگان |
| **Turso** | دیتابیس ابری (جدول رقابت، هدیهٔ سکهٔ ادمین، معرفی دوستان) | رایگان |
| **Vercel** | میزبانی خود بازی (لینک عمومی + دیپلوی خودکار) | رایگان |

> بازی به‌صورت **آفلاین هم کامل کار می‌کند** (پیشرفت در گوشی/مرورگر ذخیره می‌شود)؛
> Turso فقط برای بخش‌های آنلاین (جدول رقابت و ادمین) است.

---

## فهرست کارها (چک‌لیست کلی)

1. [ ] دانلود پکیج پروژه و باز کردن آن روی کامپیوتر شخصی
2. [ ] نصب و ورود به **GitHub Desktop** و انتشار پروژه روی GitHub
3. [ ] ساخت دیتابیس **Turso** و اجرای یک دستور برای ساختن جدول‌ها
4. [ ] ایمپورت پروژه در **Vercel** و ثبت ۳ متغیر محیطی
5. [ ] تست بازی روی لینک `*.vercel.app`
6. [ ] (اختیاری) اتصال دامنهٔ اختصاصی

---

## گام ۱ — دانلود و آماده‌سازی پروژه روی کامپیوتر

1. فایل `color-manor.zip` را از همین گفتگو دانلود کن (پوشهٔ download).
2. روی آن راست‌کلیک → **Extract All…** → مقصد را مثلاً بگذار: `C:\Projects\color-manor`
3. پوشهٔ باز‌شده را نگه دار — در گام بعد به آن نیاز داری.
4. *(فقط اگر می‌خواهی روی کامپیوتر خودت هم بازی را اجرا و تست کنی)*:
   - نصب [Node.js LTS](https://nodejs.org) یا [Bun](https://bun.sh)
   - در ترمینال داخل پوشه: `npm install` (یا `bun install`)
   - `cp .env.example .env` و سپس `npm run db:push`
   - اجرای محلی: `npm run dev` → آدرس `http://localhost:3000`

> نکته: فایل `.env` و دیتابیس محلی عمداً داخل Git قرار نمی‌گیرند (git-ignored) — هیچ رازی به GitHub نمی‌رود.

## گام ۲ — GitHub Desktop (خط به خط)

### ۲-۱ نصب
1. به آدرس [desktop.github.com](https://desktop.github.com) برو و **Download** بزن.
2. فایل نصب را اجرا کن؛ چند ثانیه بعد خودش باز می‌شود.
3. پنجرهٔ «Welcome to GitHub Desktop» → دکمهٔ **Sign in to GitHub.com** → مرورگر باز می‌شود.
4. اگر حساب GitHub نداری: اول در github.com با **Sign up** حساب بساز (فقط ایمیل و رمز)، بعد برگرد.
5. در مرورگر **Authorize github** را بزن → GitHub Desktop وارد می‌شود.
6. مرحلهٔ «Configure Git» → نام و ایمیلت را بگذار → **Finish**.

### ۲-۲ افزودن پروژه
7. از منوی بالای برنامه: **File → Add local repository…**
8. روی **Choose…** کلیک کن و پوشهٔ `C:\Projects\color-manor` را انتخاب کن.
9. چون پروژه از قبل مخزن Git دارد، برنامه فوراً آن را می‌شناسد → دکمهٔ **Add repository**.
10. حالا در ستون سمت چپ فایل‌های پروژه را می‌بینی (اگر تغییر جدیدی نباشد می‌گوید «No local changes»).

### ۲-۳ انتشار روی GitHub
11. در نوار بالای برنامه دکمهٔ **Publish repository** را بزن (داخل جعبهٔ نام مخزن).
12. پنجرهٔ کوچکی باز می‌شود:
    - **Name**: بگذار `color-manor`
    - **Description**: اختیاری، مثلاً `Mobile puzzle game — Color Manor`
    - تیک **Keep this code private**: اگر می‌خواهی فقط خودت ببینی بماند (Private)؛ برای انتشار عمومی بردارش.
13. دکمهٔ **Publish repository** را بزن → چند ثانیه صبر کن.
14. تمام! با **Repository → View on GitHub** (یا Ctrl+Shift+G) صفحهٔ مخزن را در مرورگر ببین.

### ۲-۴ کارهای روزمرهٔ بعد از این (هر بار که تغییری می‌خواهی منتشر کنی)
1. کد را ویرایش کن (مثلاً فایل‌های داخل `src/`).
2. GitHub Desktop را باز کن → تغییرات در ستون چپ دیده می‌شود.
3. در پایین چپ، در کادر **Summary** یک توضیح کوتاه بنویس (مثلاً `fix curtain anchor`).
4. دکمهٔ **Commit to main** را بزن.
5. بالای برنامه دکمهٔ **Push origin** ظاهر می‌شود → بزن.
6. تمام — Vercel خودش ۱–۲ دقیقه بعد نسخهٔ جدید را منتشر می‌کند (گام ۴).

---

## گام ۳ — دیتابیس Turso

### ۳-۱ ساخت حساب و دیتابیس (از مرورگر، بدون ترمینال)
1. به [app.turso.tech](https://app.turso.tech) برو و با GitHub وارد شو (**Sign in with GitHub**).
2. دکمهٔ **Create Database** (یا New Database) را بزن.
3. **Name**: `color-manor`
4. **Location/Region**: نزدیک‌ترین به مخاطبت، مثلاً `fra` (فرانکفورت) یا `ams` (آمستردام).
5. دکمهٔ **Create** → دیتابیس در چند ثانیه ساخته می‌شود.

### ۳-۲ گرفتن آدرس و توکن
6. روی دیتابیس `color-manor` کلیک کن → تب **Connect** (یا "Connection details").
7. مقدار **LIBSQL_URL** را کپی کن — چیزی شبیه `libsql://color-manor-<username>.turso.io`
8. دکمهٔ ساخت توکن را بزن (**Create Token** / Generate Token) → مقدار توکن را کپی کن.
9. این دو مقدار را جایی ذخیره کن — در گام ۴ به هر دو نیاز داری.

### ۳-۳ ساختن جدول‌ها (یک بار برای همیشه)
ساده‌ترین راه، نصب یک ابزار خط فرمان است (کامپیوترت فقط همین یک بار به آن نیاز دارد):

**ویندوز (PowerShell):**
```powershell
curl -sSfL https://get.turso.tech | bash
```
**مک/لینوکس:**
```bash
curl -sSfL https://get.turso.tech | bash
```

بعد از نصب، ترمینال جدیدی باز کن و به‌ترتیب:
```bash
turso auth login          # ورود با GitHub
turso db shell color-manor < prisma/turso-init.sql
```
دستور دوم، جدول‌های `Player` و `Grant` را می‌سازد (اگر قبلاً ساخته شده باشند چیزی را خراب نمی‌کند).

> جایگزین بدون نصب CLI: فایل `scripts/turso-init.mjs` را می‌توانی با Node اجرا کنی:
> `set TURSO_DATABASE_URL=libsql://… && set TURSO_AUTH_TOKEN=… && npm run db:turso-init`

## گام ۴ — Vercel

1. به [vercel.com](https://vercel.com) برو → **Sign Up** → گزینهٔ **Continue with GitHub** (سریع‌ترین راه).
2. بعد از ورود: **Add New… → Project**.
3. در فهرست مخزن‌ها، کنار `color-manor` دکمهٔ **Import** را بزن.
4. Vercel خودش تشخیص می‌دهد Next.js است — چیزی در Framework عوض نکن.
5. قبل از زدن Deploy، بخش **Environment Variables** را باز کن و این ۳ ردیف را اضافه کن:

   | Name | Value |
   |---|---|
   | `TURSO_DATABASE_URL` | همان `libsql://color-manor-….turso.io` از گام ۳ |
   | `TURSO_AUTH_TOKEN` | توکن ساخته‌شده از گام ۳ |
   | `ADMIN_KEY` | یک رمز دلخواه برای پنل مدیریت (فارغ‌الذات ولی قوی، مثل `cm-admin-7Xk2q`) |

6. دکمهٔ **Deploy** را بزن → حدود ۲–۳ دقیقه صبر کن.
7. در پایان، لینک عمومی می‌گیری، مثل: `https://color-manor.vercel.app` یا `https://color-manor-<username>.vercel.app`
8. بازی را باز کن و تست کن: بازی، جدول رقابت (🏆)، و پنل ادمین در آدرس `/admin` با همان `ADMIN_KEY`.

### تغییر متغیرها بعداً
`Project → Settings → Environment Variables` → مقدار جدید را بگذار → `Deployments` → روی آخرین دیپلوی سه‌نقطه → **Redeploy**.

### دامنهٔ اختصاصی (اختیاری)
`Project → Settings → Domains → Add` → دامنهٔ خودت را بده و طبق راهنمای Vercel، رکورد DNS را تنظیم کن.

## گام ۵ — چرخهٔ انتشار بعد از این

```
تغییر کد → GitHub Desktop: Commit to main → Push origin
        → Vercel خودکار بیلد و انتشار (۱–۲ دقیقه)
        → لینک vercel.app همیشه آخرین نسخه است
```

- **دیپلوی‌های ناموفق**: در Vercel تب **Deployments** → روی دیپلوی قرمز کلیک کن → متن خطا را بخوان؛ اکثر مواقع مشکل غلط تایپی در متغیرهای محیطی است.
- **بازگردانی نسخهٔ سالم**: در Deployments روی یک دیپلوی قدیمیِ سالم → سه‌نقطه → **Promote to Production**.

## رفع اشکال‌های رایج

| مشکل | راه‌حل |
|---|---|
| جدول رقابت خالی است و خطا می‌دهد | جدول‌ها ساخته نشده‌اند — گام ۳-۳ را اجرا کن |
| Vercel لینک باز نمی‌شود / 500 می‌دهد | سه متغیر محیطی را دقیق چک کن؛ بعد Redeploy |
| `ADMIN_KEY` پنل ادمین کار نمی‌کند | مقدار متغیر در Vercel با رمزی که می‌زنی باید یکسان باشد (حساس به بزرگی/کوچکی حروف) |
| GitHub Desktop خطای Push داد | از منو: `Repository → Open in Terminal` بعد `git pull` و دوباره Push |
| ثبت‌نام سرویس‌ها به‌خاطر محدودیت شبکه با مشکل روبه‌رو شد | از یک شبکهٔ پایدارتر استفاده کن یا با حساب Google/GitHub وارد شو |
| بازی آفلاین کاملاً کار می‌کند ولی آنلاین خیر | اول تست `scripts/smoke-test.mjs` را اجرا کن تا دیتابیس را جداگانه بسنجی |

## معماری نهایی

```
GitHub (کد)  ──push──►  Vercel (بیلد Next.js + API)
                             │
                             ▼
                        Turso (libSQL ابری)
                        Player + Grant
```

- کد بازی: `src/game/*` — کاملاً سمت کلاینت، آفلاین‌محور
- سرویس‌های آنلاین: `src/app/api/*` — جدول رقابت، همگام‌سازی، هدیهٔ ادمین، معرفی دوستان
- انتخاب خودکار دیتابیس: `src/lib/db.ts` — اگر `TURSO_DATABASE_URL` بود → Turso؛ وگرنه → فایل SQLite محلی (فقط توسعه)
- تست سلامت دیتابیس: `bun scripts/smoke-test.mjs`
